# سرور جماعت «شهر نور» — فاز ۸

سرور مرجع (authoritative) بخش اجتماعی و چندنفره. بدون هیچ وابستگی —
فقط ماژول‌های داخلی Node.js (`http`، `crypto`، `fs`، `net`).

## اجرا

از ریشهٔ مخزن:

```bash
node server/src/index.js                 # پورت پیش‌فرض 8081
node server/src/index.js --port=9001     # پورت دلخواه
node server/src/index.js --no-save       # بدون ذخیرهٔ دیسک (حافظه فقط)
```

یا با npm:

```bash
npm run server
```

سلامت سرور: `http://127.0.0.1:8081/health`
مسیر وب‌سوکت: `ws://127.0.0.1:8081/social-ws`

کلاینت بازی در حالت توسعه از همان دامنه وصل می‌شود
(`vite.config.js` مسیر `/social-ws` را به همین سرور پروکسی می‌کند).

## اصول مرجع‌بودن

- **منابع و تایمرها فقط در سرور معتبرند.** هیچ پیامی برای «تنظیم مستقیم»
  منابع یا `endsAt` وجود ندارد؛ کلاینت فقط نیت (spend/harvest/enqueue/…)
  می‌فرستد و سرور با دادهٔ JSON و ساعت خودش بازمحاسبه می‌کند.
- **ساعت سرور تنها مرجع است.** هیچ برچسب زمانی از کلاینت پذیرفته نمی‌شود؛
  پایان کار فقط وقتی قبول است که ساعت سرور از `endsAt` گذشته باشد
  (با ۱٫۵ ثانیه اغماض تأخیر شبکه).
- **برداشت سقف‌دار است.** بودجهٔ هر منبع فقط از روی نرخ تولید
  ساختمان‌های تأییدشده پر می‌شود؛ ادعای بیشتر، سقف می‌خورد.
- **پاداش‌ها از منبع مجاز با سقف** (`ledger.grantCaps` در `social.json`).
- **محدودیت نرخ** روی همهٔ اقدام‌ها (به‌ویژه چت، کمک، اهدا، گزارش).

## جماعت (به‌جای کلن)

- چت متنی با فیلتر واژه‌های نامناسب + دکمهٔ گزارش (دلیل از فهرست مجاز).
- کمک متقابل در ساخت: هر کمک ۶۰ ثانیه از تایمر کم می‌کند (سقف ۵ کمک
  و حداکثر نصف مدت کار برای هر کار).
- رویداد تعاونی هفتگی «کاروان نور» با هدف مشترک؛ با کامل‌شدن هدف،
  همهٔ هم‌سهم‌ها پاداش یکسان می‌گیرند.
- رقابت فقط دوستانه: جدول هم‌سهم‌ها نمایشی است؛ حمله، غارت و از دست
  دادن منابع وجود ندارد (اصلاً چنین پیامی در پروتکل نیست).

## حریم خصوصی و کودکان

- حداقل داده: نام نمایشی خودخواسته، پرچم کودک، لجر بازی و گزارش‌ها.
  بدون ایمیل، شماره، شناسهٔ دستگاه یا هر اطلاعات شخصی.
- تاریخچهٔ چت فقط در حافظه است (۱۰۰ پیام آخر) و هرگز ذخیرهٔ دائم ندارد.
- حساب کودک: چت آزاد بسته است (`child-restricted`)؛ فقط پیام‌های آماده.
- پرچم کودک پس از ساخت حساب هرگز تغییر نمی‌کند.

## پروتکل (خلاصه)

درخواست‌ها `{ id, type, payload }` و پاسخ‌ها `{ id, ok, ... }`؛
اعلان‌های سرور `{ push, payload }` با `push` از جنس
`ledger/chat/presence/help/event/notice`.

| type | کاربرد |
| --- | --- |
| `hello` | احراز هویت توکنی / ساخت بازیکن + عکس کامل وضعیت |
| `city:sync` | معرفی ساختمان‌ها (فقط `{type, level}` تأییدشده) |
| `ledger:harvest/spend/grant` | نیت‌های اقتصادی (سقف‌دار و اعتبارسنجی‌شده) |
| `build:enqueue/complete/speedup` | ساخت اتمی با ساعت سرور |
| `help:request/give/cancel` | کمک متقابل در ساخت |
| `chat:send/preset/report` | چت فیلتردار، پیام آماده، گزارش |
| `event:donate` | اهدا به هدف هفتگی |
| `presence:ping` / `state:pull` | ضربان و همگام‌سازی |

## فایل‌ها

```
server/
  package.json        شناسنامه (بدون dependencies)
  README.md           همین راهنما
  src/
    index.js          نقطهٔ ورود CLI
    server.js         GameServer: مسیریاب، اعتبارسنجی، انتشار، تیک، ذخیره
    ws.js             لایهٔ حداقلی WebSocket (RFC 6455) سمت سرور
    wsClient.js       کلاینت حداقلی WebSocket برای تست‌ها (بدون وابستگی)
    protocol.js       انواع پیام، کدهای خطا، اعتبارسنج‌ها
    data.js           خواندن همان JSONهای بازی از دیسک
    auth.js           توکن و بهداشت نام نمایشی
    rateLimit.js      محدودیت نرخ پنجرهٔ لغزان
    chatFilter.js     نرمال‌سازی فارسی و فیلتر واژه‌ها
    player.js         PlayerSim: لجر و تایمرهای مرجع هر بازیکن
    jamaat.js         JamaatManager: اعضا، چت، کمک، رویداد هفتگی
    store.js          ذخیرهٔ JSON با debounce
```

دادهٔ ذخیره در `server/data/server.json` (در git نادیده گرفته می‌شود).
