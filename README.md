# شهر نور — Shahr-e Nur

بازی **شهرسازی و استراتژی سه‌بعدی موبایل‌محور** با الهام از قصه‌های قرآنی.
دوربین زاویه‌دار ثابت (سبک Clash of Clans)، رابط کاملاً فارسی و RTL، و همهٔ مدل‌ها/تکسچرها
به‌صورت پیش‌فرض با کد ساخته می‌شوند؛ فونت‌های self-host با OFL و مدل‌های اختیاری CC0 در `ASSETS.md` ثبت‌اند.

> **وضعیت:** پیاده‌سازی فاز ۹ انجام شده است: چرخهٔ شب‌و‌روز، شیدر آب و باد، صدای محیطی ساخته‌شده با Web Audio، PWA آفلاین، تنظیمات دسترس‌پذیری، برچسب‌گذاری منبع/بازبینی، آزمون‌های واحد Vitest (اقتصاد + شبیه‌ساز نبرد + determinism) و درگاه انتشار PWA افزوده شده‌اند.
> آزمون‌های خودکار در این مخزن اجراپذیرند؛ سنجش FPS/حافظه روی گوشی میان‌رده، نصب واقعی و قطع شبکه باید روی دستگاه/مرورگر هدف انجام شود. درس‌ها اختیاری‌اند و غیبت جریمه ندارد.

## ۱) اجرا

```bash
npm ci
npm run dev          # http://localhost:5173
```

سایر دستورها:

```bash
npm test             # همهٔ آزمون‌ها: ۱۱۲ بررسی منطق/قرارداد (check.mjs) + آزمون‌های Vitest (از جمله regressionهای upgrade)
npm run test:unit    # فقط Vitest (economy، شبیه‌ساز نبرد، determinism، PerfMonitor)
npm run check        # نام جایگزین برای npm test
npm run smoke        # بوت کامل در jsdom، تنظیمات و آزمون‌های پذیرش یکپارچه
npm run build        # ساخت آیکن‌های کد-تولیدشده + خروجی production در dist/ + تولید sw.js
npm run test:pwa     # درگاه انتشار PWA: اعتبارسنجی dist (manifest، آیکن‌ها، precache)
npm run preview      # پیش‌نمایش build (ثبت Service Worker فقط در build تولیدی است)
```

### جداسازی لایه‌ها

- **core** هیچ‌چیز از بازی نمی‌داند (فقط موتور و ابزار) و به متن قرآن دسترسی ندارد.
- **world** فقط رندر می‌کند؛ از قرآن فقط پرچم `lesson` روی تعریف ساختمان را می‌شناسد.
- **game** هیچ‌وقت Three.js یا DOM را لمس نمی‌کند؛ فقط intent می‌خواند و رویداد می‌دهد.
  لایهٔ آموزشی هم این‌جاست و تنها با شناسهٔ آیه کار می‌کند.
- **ui** تنها لایه‌ای است که متن آیه را می‌بیند — در کارت درس و مینی‌گیم‌های `ui/quran` با نشان وضعیت و منبع.

## ۳) محتوا و خط‌قرمزها

- **متن قرآن هرگز از حافظه نوشته نمی‌شود.** `public/quran/quran.json` شامل متن منسوب به Tanzil و ترجمهٔ قرائتی است؛ در ۸ اکتبر ۲۰۲۶ پس از تطبیق بایت‌به‌بایت با آینه‌های مستقل فایل رسمی، بازبینی با رکورد قابل‌ردیابی (`meta.review`) و تأیید مالک ثبت شد (`reviewed: true`). فراداده و بلوک حق‌نشر منبع داخل فایل نگه داشته شده‌اند.
  `src/data/quran-sample.json` فقط متن‌های ساختگیِ جای‌نگهدار دارد (نه آیه/ترجمهٔ واقعی) و با نشان «نمونه — جایگزین شود» نمایش داده می‌شود.
- `npm run check` آزمونی دارد که تمام فایل‌های کد/داده را اسکن می‌کند و اگر واژه‌ای با
  اعراب کامل (امضای متن قرآن) بیرون از فایل دادهٔ نمونه پیدا شود، تست شکست می‌خورد.
- متن آیه فقط داخل رابط درس نمایش داده می‌شود، همیشه با کلاس `quran-text` (فونت قرآنی +
  اعراب کامل)، همراه ترجمه، منبع و برچسب‌های وضعیت. آزمون‌ها بررسی می‌کنند که متن آیه
  نه در صحنهٔ سه‌بعدی، نه در HUD، نه در فایل ذخیره و نه در گزارش‌ها نباشد.
- آیه‌های بازبینی‌نشده با نشان **«در انتظار بازبینی»** و آیه‌های جای‌نگهدار با نشان
  **«نمونه — جایگزین شود»** دیده می‌شوند. با `reviewed: true` در دیتاست معتبر، نشان برداشته می‌شود.
- تلاوت اختیاری و خاموش‌پیش‌فرض است؛ فقط با نام مجوز و نشانی انتساب امن پخش می‌شود و در تنظیمات می‌توان آن را خاموش کرد. صدای باد/آب/پرندگان به‌صورت محلی ساخته می‌شود؛ موسیقی سازی وجود ندارد.
- هیچ تصویر یا مدلی از پیامبران، ائمه و فرشتگان ساخته نمی‌شود؛ مدل «دارالقرآن» فقط
  هندسهٔ low-poly و کاشی‌کاری هندسی است و هیچ متن یا تصویری روی سطح آن نیست.
- بدون قمار/جعبهٔ شانسی و بدون خشونت گرافیکی. «گوهر» فقط از مسیرهای درون‌بازی به دست می‌آید
  و درس‌ها هیچ هزینه‌ای ندارند: نه ورودی می‌خواهند، نه برای خطا جریمه می‌کنند.

## فاز ۱۰ — بازطراحی HUD موبایل (ارگونومی ناحیهٔ شست)

HUD از شش گوشهٔ `position:absolute` به دو ناحیهٔ تمام‌عرض تبدیل شد:
**نوار وضعیت** (فقط نمایش: سطح شهر/بازیکن، رزق/نور/حکمت/گوهر، چرخ‌دندهٔ تنظیمات) و
**داک کنش** (پنج کنش ≥۴۸px در دسترس شست: ساخت‌وساز، دارالقرآن، قصه‌ها، جماعت، کارنامه).
شمار بنّاها به نشان روی دکمهٔ «ساخت‌وساز» منتقل شد، دکمه‌های پادگان/نبرد و برچسب
کم‌کنتراست «راهنمای متن» از روی نقشه به بخش «سپاه، نبرد و متن‌ها» در کارنامه رفتند، و
صف ساخت/منوی انتخاب/نوار جانمایی در یک ستون flow بالای داک می‌نشینند (بدون افست
پیکسلی ⇒ بدون هم‌پوشانی در هر عرض و هر مقیاس فونت). ریشهٔ HUD `pointer-events:none`
است تا پن/زوم زیر فضاهای خالی همچنان کار کند، `env(safe-area-inset-*)` در چهار جهت
رعایت می‌شود، و در حالت افقی داک به ریل کناری تبدیل می‌شود.

- **نمای کلی، جدول قبل/بعد و روش اندازه‌گیری:** `docs/hud-redesign/README.md`
- **بررسی خودکار هندسه (۱۶۹ سنجه، Chromium/SwiftShader):** `npm run test:hud`
- **تصاویر قبل/بعد:** `docs/hud-redesign/before/` و `docs/hud-redesign/after/` (`npm run hud:screenshots`)
- **آزمون واحد قرارداد HUD (jsdom):** `tests/hud.test.js`
- **محدودیت:** اعداد این بخش هندسهٔ چیدمان‌اند (واقعی، اندازه‌گیری‌شده) و نه عدد
  کارایی GPU؛ اجرای SwiftShader هیچ ادعایی دربارهٔ فریم‌ریت روی دستگاه نمی‌سازد.

## فاز ۲ — چیدمان ساختمان و HUD

این نسخه فروشگاه فارسی، اقتصاد اولیه، اشغال گرید و جانمایی لمسی سازه‌ها را اضافه می‌کند.
ساختمان را از «ساخت‌وساز» انتخاب کنید، پیش‌نمایش را روی نقشه بکشید و در محل سبز
«تأیید ساخت» را بزنید. قطعهٔ دیوار پس از هر تأیید برای ادامهٔ ردیف فعال می‌ماند؛ با «لغو»
از حالت ساخت خارج شوید. لمس یک ساختمان ساخته‌شده منوی اطلاعات و ارتقا را باز می‌کند.

## فاز ۳ — اقتصاد و زمان

سه منبع **رزق / نور / حکمت** با ظرفیت انبار (پایه + پاداش هر انبار آماده) و سقف بافر تولید؛
تولیدکننده‌ها با نرخ در ساعت و برداشت با تپ روی ساختمان وقتی به «آمادهٔ برداشت» رسیده باشد.
ارتقای ساختمان با منحنی هزینه/زمان تا سطح ۱۰ (`src/data/balance.json`)، ساخت با صف دو بنّا و
تایمر زندهٔ فارسی، و **سرعت‌بخشی فقط با گوهر** (ارز درون‌بازی؛ بدون خرید پولی، قمار یا جعبهٔ شانسی).
ذخیره و بازیابی با IndexedDB (نسخهٔ schema + مهاجرت) و پیشرفت آفلاین از روی timestamp هنگام
بازگشت — با سقف ظرفیت انبار؛ ساعت عقب‌رفته/جلوترفته هم خطا نمی‌دهد.

## فاز ۴ — لایهٔ قرآنی-آموزشی (هستهٔ تمایز بازی)

**ساختمان «دارالقرآن»:** از فروشگاه ساخته می‌شود (۳×۳، تولید حکمت) و با تپ روی آن یا دکمهٔ
«۞ دارالقرآن» در HUD باز می‌شود. پنل آن فهرست درس‌ها، وضعیت دیتاست، آمار مرور و استخر تسریع
را نشان می‌دهد. متن آیه در همین پنل و فقط پس از ورود به درس دیده می‌شود.

**درس‌ها (۲ تا ۳ دقیقه):** هر درس از مرحله‌های داده‌محور ساخته می‌شود:
`read` (خوانش آیه با ترجمه، منبع و برچسب‌ها) → `quiz` (یکی از سه مینی‌گیم) → `summary`
(جمع‌بندی و پاداش). چهار درس نمونه در `quran-sample.json` تعریف شده و برای جایگزینی با
دیتاست واقعی فقط فایل دادهٔ درس‌نامه (یا خود دیتاست) عوض می‌شود.

**سه مینی‌گیم:**

| مینی‌گیم | روش بازی | داده |
| --- | --- | --- |
| تکمیل آیه | یک واژه از متن پنهان است و از میان ۴ گزینه انتخاب می‌شود | واژه‌ها از خود آیه و سایر آیه‌های دیتاست |
| تطبیق واژه و معنی | واژه را بزن، بعد معنی‌اش را | `wordBank` درس یا جفت «آیه ↔ ترجمه» |
| ترتیب آیات | دو کارت را پشت‌سرهم بزن تا جابه‌جا شوند؛ «بررسی ترتیب» جای‌های درست را قفل می‌کند | آیه‌های قطعه یا بخش‌های یک آیه |

هر سه مینی‌گیم «راهنما (بدون جریمه)» دارند و پاسخ نادرست فقط گزینه را خاموش می‌کند.

**مرور فاصله‌دار (لایتنر):** هر آیه و هر جفت واژه یک «قلم» است. پاسخ درست یک جعبه بالا
می‌رود (۱۰ دقیقه → ۱۲ ساعت → ۳ روز → ۷ روز → ۲۱ روز) و پاسخ نادرست به جعبهٔ ۱ برمی‌گردد و
در همان نشست دوباره نشان داده می‌شود. نشان تعداد موارد در نوبت مرور روی دکمهٔ دارالقرآن دیده
می‌شود و با «شروع مرور» یک نشست کوتاه ساخته می‌شود.

**اتصال به اقتصاد (اختیاری، فقط تسریع‌کننده):**

| مسیر | نور | حکمت | تسریع ساخت |
| --- | --- | --- | --- |
| تکمیل درس | +۴۵ | +۳۰ | ۹۰ ثانیه |
| نخستین تکمیل درس | +۶۰ | +۴۰ | ۱۲۰ ثانیه |
| درس بدون خطا | +۱۵ | +۱۰ | — |
| نشست مرور | +۱۲ | +۸ | — |

پاداش‌ها هرگز از سقف انبار رد نمی‌شوند (سرریز فقط گزارش می‌شود)، هیچ‌وقت منابع را کم نمی‌کنند و
هیچ خطا یا ترک‌کردن درسی جریمه ندارد. «تسریع ساخت» تایمر بنّای فعال را کوتاه می‌کند و اگر بنّایی
مشغول نباشد در استخری (سقف ۳۰۰ ثانیه) ذخیره می‌شود.

**راستی‌آزمایی:**

```bash
npm run check        # شامل:
                     #  • جای‌نگهدار بودن کامل دیتاست نمونه و برچسب‌های بازبینی
                     #  • جایگزینی دیتاست به سبک Tanzil بدون تغییر کد + بازگشت ایمن در خطا
                     #  • بازی‌پذیری و بی‌جریمه‌بودن هر سه مینی‌گیم
                     #  • صعود/سقوط جعبه‌های لایتنر و بازگشت اقلام خطادار
                     #  • افزوده‌شدن پاداش به منابع، احترام به سقف انبار و کوتاه‌شدن تایمر بنّا
```

## فاز ۵ — سپاه و نبرد PvE

این فاز واقعاً در مبنای main `9b64be9` موجود بود؛ Open بودن PR #5 هنگام ممیزی نشانهٔ نبود کد نیست. پادگان، چهار نقش faceless، استقرار، A*، برج/دیوار، نتیجه و بازپخش وجود دارند. شبیه‌ساز گام ثابت **۲۰Hz** و RNG بذر‌دار دارد و به DOM/Three.js/ساعت وابسته نیست.

Upgrade سناریو/record را به **v2** و save را با migration **۶→۷** نسخه‌دار می‌کند. قاعدهٔ ترک میدانِ ستون ضعیف در `battle.json` است؛ fixture حقیقی v1 تمام hash/checkpointهای قبلی را حفظ می‌کند. UI پادگان/نتیجه/replay آزمون smoke مستقل دارد. جدول ۴۳ سناریو و ۸۶ replay در `docs/upgrade/after/battle-matrix.json` است.

## فاز ۶ — کمپین قصص

زنجیرهٔ مأموریت‌ها، هدف‌های سه‌ستاره، قواعد قحطی/سد/آبادانی و ذخیرهٔ اجرای نیمه‌کاره در main موجودند. درس و کمپین اختیاری‌اند و غیبت جریمه ندارد. هیچ تصویر پیامبر/امام/فرشته و هیچ متن قرآنی روی صحنهٔ 3D نیست. کد نمایش ارجاع/آیه در `src/ui/quran/` است. منطق مأموریت ذخیره‌شده پیش از bootstrap و بخش‌های تازه هنگام تعامل load می‌شوند.

## وضعیت واقعی دیتاست آموزشی

فایل عمومی فعلی **۱۱۴ سوره / ۶۲۳۶ آیه** دارد: متن منسوب به Tanzil Uthmani 1.1 و ترجمهٔ قرائتی با provenance داخل فایل. `reviewed:true` **تغییر نکرده** است. رکورد موجود از تأیید مالک `abolfazlghasemi2001` در ۲۰۲۶-۱۰-۰۸ و تطبیق مکانیکی/ساختاری با آینه‌ها خبر می‌دهد؛ این ممیزی آن را تأیید مستقل دینی/حقوقی نمی‌نامد. مدرک بازبینی واجدصلاحیتِ مستقل هنوز در ریپو نیست و **پیش از انتشار محتوایی به بررسی انسانی نیاز است**. SHA-256 فقط تمامیت بایت‌ها را اثبات می‌کند.

شبکه پس از idle/تعامل، با مسیر same-origin، schema، سقف ۸MiB، timeout و checksum کار می‌کند. fallback همان نمونهٔ برچسب‌دار است، نه متنی از حافظه. `dist/quran/quran.json.br` خروجی فشرده است؛ dev/preview با Content-Encoding: br خدمت می‌دهند. در میزبان static واقعی تنظیم Brotli را فعال کنید. خط‌مشی update PWA: پیشنهاد روشن → ذخیرهٔ پایدار → رضایت reload؛ در خطای IDB یا private mode، update عقب می‌افتد.

## فاز ۷ — متاگیم و تجربهٔ کاربر

- **FTUE تعاملی:** ۱۱ گام قابل‌ردکردن با نشانگر و هایلایت هدف، از فروشگاه و نخستین مزرعه تا برداشت، درس و گسترش شهر. پیشرفت رویدادمحور است؛ از «تنظیمات» یا «کارنامه» می‌توان راهنما را دوباره مرور و پیش از پایان بست.
- **مسیر ۳۰ دقیقهٔ نخست:** هشت بازهٔ پیشنهادی در کارنامه ثبت می‌شوند. زمان فقط در بازی فعال جمع می‌شود؛ پیشنهادهای دقیقه‌ای شمارش معکوس نیستند و هیچ قابلیت یا پاداشی با گذر زمان حذف نمی‌شود.
- **کارنامه:** سطح و XP نمایشی، دستاوردها، مأموریت/تمرین اختیاری و وضعیت مسیر ۳۰ دقیقه ذخیره می‌شوند. XP خریدنی نیست و توان رزمی نمی‌دهد.
- **تنظیمات:** کیفیت پایین/متوسط/بالا، صدا، منطقهٔ فارسی ایران/افغانستان و صرفه‌جویی باتری در ذخیره نگه‌داری می‌شوند. تغییر کیفیت روی DPR، مه و سایه‌ها اثر می‌گذارد؛ صرفه‌جویی باتری واقعاً سقف رندر را ۳۰fps می‌کند و سایه‌ها را خاموش می‌کند. برنامه فعلاً فقط فارسی و راست‌چین است.
- **سه رعایت روشنِ نبود الگوی تاریک:** (۱) تمرین روزانه مهلت، streak و جریمهٔ روز ازدست‌رفته ندارد و پیشرفت نیمه‌کاره پاک نمی‌شود؛ (۲) ورود روزانه/غیبت هیچ گوهر، امتیاز یا پاداش ازدست‌رفتنی نمی‌دهد؛ (۳) تبلیغ، اعلان مزاحم، شمارش معکوس یا اجبار به درس/خرید وجود ندارد و XP فقط کارنامه‌ای است.
- **راستی‌آزمایی فاز ۷:** `npm run check` آزمون منطق متا/ذخیره/نبود جریمه و هدف ۳۰fps را اجرا می‌کند؛ `npm run smoke` رابط واقعی FTUE، تنظیمات زنده، بازبینی راهنما و ماندگاری تنظیمات و پیشرفت را در jsdom می‌سنجد.

## فاز ۸ — جماعت و رقابت دوستانه (مولتی‌پلیر اختیاری)

- **سرور جدا (`server/`، بدون وابستگی):** Node.js + وب‌سوکت خام (RFC6455)، مرجع منابع/تایمرها/ظرفیت. توکن تصادفی، rate-limit لغزشی، فیلتر فحاشی فارسی/عربی، گزارش محتوا (ذخیره می‌شود؛ خود چت هرگز ذخیره نمی‌شود). اجرای سرور: `npm run server` (پیش‌فرض `127.0.0.1:8081`، مسیر `/social-ws`؛ راهنمای اپراتور در `server/README.md`).
- **اتصال از بازی:** دکمهٔ «◈ جماعت» در HUD (با نشان پیام/کمک)، یا خودکار با `?social=ws://…`. پیش‌فرض کلاینت same-origin (`/social-ws`) است و vite در حالت dev آن را به سرور پروکسی می‌کند. قطع اتصال = بازگشت تمیز به حالت محلی؛ آفلاین هیچ تغییری در رفتار بازی نیست.
- **اقتدار سرور:** ساخت/ارتقا/تسریع آنلاین فقط با تأیید سرور (جای موقت `hold` + rollback خودکار در رد/قطعی)؛ اتمام کارها فقط با ساعت سرور؛ دست‌کاری منابع در کلاینت هیچ اثری روی سرور ندارد (تست‌شده).
- **جماعت (نه کلن):** چت با فیلتر + دکمهٔ گزارش، کمک متقابل کوتاه‌شدن تایمر (سقف ۵۰٪، cooldown دهنده)، هدف هفتگی «کاروان نور» با پاداش مساوی گوهر. رقابت فقط دوستانه: بدون غارت، بدون از دست دادن منابع، بدون حمله.
- **حریم خصوصی:** فقط نام نمایشی + توکن؛ حساب کودک چت آزاد ندارد (فقط پیام آماده).
- **راستی‌آزمایی فاز ۸:** `npm run check` (واحد فیلتر/محدودیت/توکن + e2e دوکلاینته روی سوکت واقعی + تست SocialClient) و `npm run smoke` (پنل آفلاین، خطای اتصال، و لینک واقعی سرور↔بازی↔پنل با کمک از راه دور).

## فاز ۹ — صیقل و انتشار (بتای قابل‌انتشار)

- **هنر:** شيدر آب (موج و درخشش، رنگ روز/شب) و شيدر باد برای برگ‌ها با `onBeforeCompile` (بدون draw call اضافه)؛ چرخهٔ شب‌و‌روز با نور خورشید، hemisphere، مه و آسمان گرادیانی (SkyDome)؛ انیمیشن‌های نرم UI (transitionهای ۱۲۰ تا ۴۰۰ میلی‌ثانیه)؛ در حالت کاهش حرکت همهٔ انیمیشن‌ها خاموش‌اند.
- **صدا:** باد، آب و آواز کوتاه پرنده با Web Audio در خود مرورگر ساخته می‌شوند (بدون فایل صوتی). تلاوت قرآن اختیاری است، پیش‌فرض خاموش، و در تنظیمات خاموش می‌شود. موسیقی وجود ندارد.
- **PWA:** `manifest.webmanifest`، Service Worker با precache (پوسته + assetهای هش‌شده + آیکن‌ها + دیتاست قرآن)، آیکن‌های ۱۹۲/۵۱۲ که با کد تولید می‌شوند، ثبت خودکار فقط در build تولیدی. `npm run test:pwa` خروجی `dist/` را اعتبارسنجی می‌کند (installable + offline shell).
- **بهینه‌سازی:** `PerfMonitor` از صف شیء در هر فریم به ring buffer از پیش‌تخصیص‌یافته (`Float64Array`) تبدیل شد: بدون allocate در هر فریم و حدود ۱۵ برابر سریع‌تر، با همان مقدار FPS. گزارش قبل/بعد در `PERFORMANCE_REPORT.md`.
- **آزمون واحد (Vitest):** `tests/economy.test.js` (منطق اقتصاد: ظرفیت، تولید، برداشت، آفلاین، determinism)، `tests/battle-sim.test.js` (شبیه‌ساز نبرد: determinism با بذر/دستور یکسان، گام ثابت، بازپخش/اعتبارسنجی سرور، A*) و `tests/perf-monitor.test.js`. اجرا: `npm run test:unit`.
- **دسترس‌پذیری:** اندازهٔ فونت (۳ گام)، کنتراست بالا و حالت کاهش حرکت در تنظیمات ذخیره می‌شوند و روی `documentElement` اعمال می‌شوند (`--ui-font-scale`، کلاس‌های `is-high-contrast` و `is-reduced-motion`).
- **انتشار:** `CONTENT_REVIEW.md` (فهرست متن‌های قرآنی/دینی و جای ورود دیتاست معتبر برای بازبینی کارشناس دینی) و `PRIVACY.md` (خلاصهٔ داده‌های ذخیره‌شده، به‌ویژه برای کودکان) به‌روز شده‌اند.
